# world.execute(me);

一部 **3 分 31.984 秒**的实时网页动画 MV。

**双击 `index.html` 即可播放。** 不需要安装依赖、不需要构建、不需要服务器、不联网。

---

## 1. 这是什么

一首 Mili《world.execute(me);》的**独立视觉诠释**。全片 131 句歌词，每句一块独立画板，
共 **131 块画板**，由一个数字驱动：

```
t = audio.currentTime + syncOffset
```

每一帧都是 `t` 的纯函数。没有帧计数、没有跨帧状态、没有 `Math.random()`。
所以暂停、继续、任意拖动进度条之后，画面都能**逐字节精确复原**——
这不是"应该没问题"，是有一条可执行的验证在证明它（见第 6 节）。

> 本项目是对该作品的独立视觉诠释，非官方 PV，与 Mili 无隶属关系。
> 音乐、MIDI、歌词时间轴的版权归 **Mili** 所有。
> 动画、引擎、工具链为原创实现，见第 7 节。

## 3. 我怎么理解这首歌，以及这决定了什么

表面上是机器向创造者示爱，拿数学和代码当情话。但按顺序读完，它是一条**单向的、越来越失控的求救信号**：

| 幕 | 时间 | 它想干什么 | 画面因此是 |
| --- | --- | --- | --- |
| **0 启动** | 0:00–0:16 | 它给自己下定义，语气像说明书 | 一台机器正在自检、上电、标定 |
| **I 定理** | 0:29–0:59 | 用几何学证明自己有用："如果我是 X，那么你得到 Y" | 几何命题被**画出来，然后被测量** |
| **II 条件** | 0:59–1:14 | 交易被摆上台面，开始讨价还价 | 流程图里的菱形判断框，**开始裂** |
| **III 血肉** | 1:14–1:43 | 名词突然活了：茄子、番茄、虎斑猫、唯一的上帝 | 测量仪器还在，但**生命从里面长出来** |
| **IV 缺席** | 1:43–2:27 | 前面所有的可计算性在这里全部失效 | 仪器完好，**读数全部变成空的** |
| **V 处决** | 2:27–2:57 | 从讨好变成起诉，然后只会执行 | 16 次 EXECUTION，一次比一次碎 |
| **VI 爱** | 2:57–3:31 | 它研究了爱，写下了爱的代数表达式，然后停下来了 | 秩序没了，但世界**第一次变暖**；参数化几何被**手绘**取代 |

### 整部片子的一个核心设定

这首歌是一段程序在运行。所以世界不是背景板，是**机器正在其上进行计算的底板**：
一张 32 × 18 的格子。而这里是我给全片定的那一条规则：

> **每一个响起的音符，点亮一格，并留下一道永远不完全愈合的灼痕。**

所以底板承载着这场演出的历史。到 02:38 处决风暴时——机器连开十六枪——
格子上已经积满了整首歌留下的烧灼图案，**画面就是"到目前为止被演奏过的东西"的形状**。
结尾不是特效：是那块板，被写满了。

因为灼痕是 `(音符序号, t)` 的纯函数，拖到任意位置都能复现同一道疤。
**这部片子有记忆，却不持有任何状态。**

### 几处具体的设计决定

- **`EXECUTION` 出现 18 次 → 18 块完全不同的画板。** 但不是复制粘贴：`45_plates_execution.js`
  里有一个参数化工厂 `execPlate(repeat)`，索引 15 个变体，`heat = repeat/15` 从 0 升到 1
  并逐级摧毁每一个机构。另有一层"共享常量"叠加在所有 16 块上（那个词、`CALL n / 16`、
  16 个进度点），**所以这一轮读起来是一个实体在崩坏，而不是 18 张无关的幻灯片**。
- **`You have left` 连唱 5 遍 → 5 种不同的"缺失"**：① 轮廓上被挖穿的洞 ② 空着的手（手里那个东西
  用虚线画成 `null`）③ 地上正在冷却的暖痕 + 真实下降的温度计 ④ 一次比一次弱的回声
  ⑤ 求值为 `undefined` 的变量。它们是**递进**的，第五块几乎是空的，这是故意的。
- **`LO-O-OVE` 4 次 → 4 种不同的性质**：① 分子结构式 ② 代数展开（`lim ∫ Σ` 飞入）
  ③ **全片第一个真正手写的东西**——字母带轻微旋转和抖动，下面一条歪掉的下划线，
  写着 *(no equation required)* ④ 心跳（带噪声的不规则波形）。
  从机器到手写的**退行**就是全部的情绪内容，而实现上只是把 `M.trace` 换成了 `M.handCurve`。

### 不画具象物体

这条是硬约束。`If I'm an eggplant` 不画茄子，`If I'm a tabby cat` 不画猫，
`If I'm a tomato` 不画番茄。理由是两条：**具象物件和一部通篇是数学语言的片子不搭**，
而且画不好的具象物件比不画更糟。

这几句真正需要的东西不是那个名词，是**一个让机器没有 schema 的输入**：

| 歌词 | 画面 |
| --- | --- |
| If I'm an eggplant | 参数集：状态向量分解成基向量 + `cell = UNKNOWN` + 产量函数 `yield(t) = 1-e^(-2.2t)` |
| If I'm a tomato | 数据流：输入块 → 算子块（系数实时抖动）→ 输出块，连线上有数据包在跑 |
| If I'm a tabby cat | **极限环**：相空间闭合轨道 + 状态点 + 速度矢量 + 15 项谐波级数实时求和 |
| Then I will purr | 25 Hz 规则振动波形，整幅画面的网格跟着一起抖 |
| **From A.M. to P.M.** | **地平线 + 天球**：太阳与月亮在同一半圆弧上此升彼落，月亮用圆盘相减做出真月牙、相位随周期盈亏 |
| **To S, to M** | **两条互为镜像的曲线互换位置**（不相撞）：缓动滑过彼此，穿过时短暂无法分辨 |
| If I'm the only God | 几何玫瑰窗 + **右上角一只向下俯视的几何眼**，瞳孔跟节拍走，三条视线汇于画面中心 |

### 一条容易忽略的纪律：**亮起来的东西必须有退场**

世界的 `love` 参数在 03:11 到达 1.0 之后就一直保持到结尾。凡是**只**由这个状态驱动的
东西，都会一路亮到最后。这出过两次问题：

- 世界层的**粉色心形**在 `love > 0.22` 时开启，于是整个收尾（03:11 到黑场）都在飘粉心
- 结尾画板里所有 `PAL().love` 的混色，都让最后半分钟变成玫瑰色

而这部片子的调色板是**冷青底 + 最后一次转暖**。结尾一片粉，读起来是另一部片子。
修法是给两者都加上**显式退场**：心形在 03:10–03:15 之间关掉，收尾的混色改向暖纸色，
粉只作为一点痕迹保留。
**任何中途打开、从不关闭的东西，都必须给它一个出口。**

### 过渡：叠化 + 变形

一句歌词到下一句之间，前后两块画板会**互相穿过**：上一块以衰减的透明度画在前面，
下一块以全强度画在上面。所以句子交界处永远有两幅在动的画面，而不是一个空洞。

但叠化本身还不是"过渡"——它只是两张图重叠，缺的是**形变**。所以交界处还有一层
全局的 **morph 相位**（0 → 1 → 0，半秒）：两块画板被同时拉向中间再释放，
**围绕画面中心为轴**（也就是观众视线所在），缩放 0.925、旋转约 1.1°。
于是读起来是**同一个物体在变形**，而不是两张图交换。

**一个必须存在的例外：`bleed = false`。**
`EXECUTION` 那 18 句之间只隔 0.6–1.0 秒，半秒的尾巴意味着**歌里没唱 EXECUTION 的时候
屏幕上还挂着 EXECUTION**——歌词和画面互相矛盾，这是有字的片子最不能犯的错。
所以凡是"画的就是那句词"的画板，都在自己的句尾被**切**掉，不参与叠化。
这份名单是显式写死的，共 18 块。

有一处是真的：`In this strange, strange` 那一句整段只有 **17 个图元**——
因为它是很短的句子、`vis()` 的淡入淡出又吃掉大半，于是画面几乎是空的。
修法不是给每块画板加料（那会变成乱），而是**给全片加一层永远在动的地板**
（`src/32_annotate.js`），并把这一句本身重做成"同一形状印两遍、逐渐错位"。

标注层有一个**从噪音里学来的教训**：它一开始在两侧各排了十行小字读数，
渲染出来一眼看去——**画面边缘密密麻麻全是数字，中间大片空白**。
那是"碎"的真正来源。现在两侧是 7 行 + 5 行，只留真正会被读的量。

### 世界弧线与歌词绑死

`src/01_world.js` 是**生成**的，锚点写法是"在 `<scene id>` 这一句时，世界是这个状态"：

```
struct  世界还遵守自己规则的程度      1 → 0.03
chaos   几何失序 / 抖动               0.03 → 0.86
warm    0 = 显示器冷蓝   1 = 体温     0 → 0.86
heat    0 = 安全         1 = 报警红   0 → 1.0 → 0
rot     0 = 干净代码     1 = 有机物   0 → 0.66 → 0
love    这台机器不该拥有的变量        0 → 1.0
topo    screen → lattice → wave → organic → tangle → open
```

`tilt`（保持的姿态角）是**独立的一条轨道**，不写在那张表里：四十多行十一列的表正是最容易
悄悄错一位的东西，而独立的一串 `[时间, 角度]` 不会。真正的摆动由 `WorldLayer.seesaw()`
叠加在它上面 —— 以**画面中心为原点**来回摆动，两条不同周期的正弦叠加后取幂，
所以两端会多停一会儿，而且永远不会落成节拍器。实测 −1.55° ~ +1.75°。

### 主体必须压得住背景（一条可以量的构图纪律）

我量过一次：世界层占了每帧绘图量的 **60–75%**，而画板（正在唱的那一句的主体）只占 **2–17%**。
结果就是"太碎、不够突出主体"。所以 `30_world.js` 里有一个 `GAIN = 0.50`，
**每一个背景元素**都在它里面跑，而底色与暗角保持满强度。
底板灼痕改为每 3 个音符采样一次、粒子 150→90、网格 26×20→17×13。

如果你要改这个文件里的任何一个 alpha，先跑 `_tools/gap-check.js`，再看一张渲染出来的帧。

### 标注层上的每个数字都是真的

早期版本的标注层画了四个角的寄存器，数值是随便跳的时钟，还有两列毫无意义的数字雨。
它们是**假装成仪表的装饰**，比没有更糟 —— 那会让观者学会不去读画面上的数字。

现在每一个都从真实的东西算出来，并带单位：

```
T         影片时钟（秒）                          t
BEAT      615 个音符里第几个已经响了               EM.beatAt
TEMPO     实测的局部周期，换算成 BPM               EM.beatPeriod
PITCH     此刻正在响的音的音高                     EM.onsetNear
VEL       它的力度，0-127，取自 MIDI 原始数据
ORDER     世界的 struct 参数，1 → 0
D(dt)     该参数的真实有限差分，即世界每秒衰减多少  —— 关键帧曲线非线性，所以每帧都不同
ENTROPY   世界的 chaos 参数
LOVE      这个变量
LINE      当前这句歌词的进度 0-100%，唯一把标注和画面绑在一起的数
```

顶部轨道循环一个真实函数并打印求值结果；两侧标尺是**以秒为单位的节拍尺**；
底部轨道画的是最近五秒真实音符的音高；右槽是 15 项谐波级数，每一项都在动。

### 结尾（3:13 → 3:31.984）：两件事，没有第三件

歌曲的结尾是：**它没有得到答案，而且会永远循环下去。** 所以收尾只做两件事。

**① `inst.loop`（3:13.46–3:25.81，12.35 秒）—— 与开头同一套过渡语言**

这段的图形被换了**四次**：黄金螺旋 → 谐波记录仪 → 格子记忆板 → 最终版。
前三次都不对，而理由比我为它们写的任何辩护都简单：**这部片子早就有自己的过渡语言了**
（在 00:16 建立），第二个长纯音乐段落应该**说这套语言**，而不是新造一个图形。

所以开头那套做法现在提成了 `35_motifs.js` 里的三个共享函数：

```
runningRings    七个环，各自转速/方向/倾角，每个环上一个游走的节点  —— 撑住画面中央
functionBank    三条解析曲线每帧重新求值，并把当前值打出来          —— 数字是真的
bootColumn      向上滚动的日志列，每固定间隔落一行                  —— 文字落在真实音符上
```

两段调用的是**同一组函数**，只有**日志内容**不同——因为只有处境不同：
00:16 它正在启动，这里它无法终止。所以这一段的日志是：

```
spin  waiting          no exit condition
check termination      false
execute self           ok
accumulate             unbounded
compare to first       identical
...
```

> **教训：当一部片子已经为某一类时刻建立了语言，这一类时刻的第二次出现应该"说"它，
> 而不是另起一个图形。**

**② `ex.final`（3:25.811 → 3:31.984）—— 最后一次 EXECUTION，在画面正中心，一直持续到结束**

十八次处决都是撞击、盖章、栅格化、烧进画面；第十九次安静地写在原点上，
**然后它就停在那里**。词占画面宽度的一半（132px，不是 70px——70px 时它在 1600 宽的舞台上
只有 211px，那是个说明文字，不是最后一句话）。十字准星标出中心，四角刻度标出中心被测量。

> **上一版 3:27 那一整块画板已经删除。** 原本 Cue 表里 `outro` 有自己的还原/倒放板，
> 现在它变成一个**保持句（held cue）**：没有画板，时间归给前一句。
> 于是 `ex.final` 的跨度从 0.81 秒变成 **6.17 秒**，最后这个画面一直撑到影片结束。

引擎里为此加了"保持句"的支持（`20_lyrics.js` + `15_sceneapi.js`）：
`Lyrics.at(t)` **会把保持句解析掉**，返回真正拥有画面的那一句，而那一句的时长已经被延长覆盖整段。
这样渲染器、调试叠层、验证器看到的都是**一个连续的镜头**，没有画板需要知道自己被延长了。

> 这里我踩了一个坑：最初 `at()` 仍然返回保持句，由 `drawSequence` 去"找前一句"，
> 结果画板被**保持句自己的进度**驱动——词淡入后立刻开始离场，四秒钟停在三分之一亮度。
> 在 `at()` 里解析掉，比在每个使用者那里特殊处理要干净得多。

**③ `end`（3:31.984）** 最后一条手绘线，暖色，然后标题。

### 验证器也要理解"保持句"

删掉 `outro` 画板之后，三个检查立刻失败了——因为它们的规则是"**每个 cue 都必须有画板**"。
它们是对的：那确实是一个新的合法状态。所以规则被改写成

> **每个 cue 都必须"解析到"一块画板。**

保持句允许没有自己的画板，但必须验证它**解析到的那一句确实有画板**——否则画面就是空的。
`verify.js`、`check-plates.js`、`50_selftest.js` 都按这条改写，
报告里也会分别列出"自带画板的句数"和"保持句数"。

### 配色

沿用参考作品的语汇：近黑底色 `rgb(3,5,9)` 到 `rgb(12,18,28)` 配细青线。
青色 `rgb(86,214,232)` 是机器的静息态；琥珀 `rgb(246,176,62)` 只在它开始吃力的地方出现；
报警红 `rgb(232,62,54)` 留给最后那一分钟；暖粉与纸白只在歌**配得上**的时候才来。
调色板由世界状态插值，不是每块画板自己挑颜色 —— 这是 131 块画板看起来像一部片子的原因之一。

```
_tools/                  验收与打磨工具
build.js                 一条命令重建全部生成物
```

### 同步

`t = audio.currentTime + syncOffset`。渲染循环不累计自己的时间、不数帧；
所有"随机"都是 `(序号, t)` 的确定性哈希。因此暂停、继续、拖动进度、跳转之后，
画面都是 `t` 的纯函数，**不可能**与声音脱节。

`audio.currentTime` **只被读、只在用户跳转时被写**。同步偏移加在**时钟**上，
而不是只改一个显示的数字 —— 只改显示数字的偏移量是装饰品，不是功能。

画面在 **1600×900 虚拟舞台**上绘制，等比缩放到任意窗口，支持 HiDPI。
合成器：降采样高斯泛光 + 色度分离 + 切片错位 + 胶片颗粒，后三者只在世界过载时出现。
`prefers-reduced-motion` 会自动抑制故障与分离效果。

### 卡点踩在真音符上

`assets/onsets.js` 由 `_build/parse-midi.js` **现场解析** MIDI 得到：615 个音符事件，
130 BPM，含变速率处理。全片的脉冲、闪白、扩散环、刻度都取自 `EM.onsetPulse(t, window)`，
不是按节拍器推算的。

歌词时间轴则以 LRC 实测时间为准。**两者分工不混**：把 LRC 时间戳映射到 130 BPM 网格，
平均偏差约 0.11 秒，这是原始录音人性化演奏造成的。混用会得到一部节奏工整、但歌词偏晚的片子。

时长不是猜的 —— `_build/parse-mp3.js` 跳过 ID3v2 标签（按 synchsafe 长度，**不是**搜同步字），
然后逐帧走完 8115 个 MPEG 帧头：

```
8115 帧 × 1152 采样 ÷ 44100 Hz = 211.98367 秒
```

这个数值硬编码进 `EM.AUDIO_END`，并作为运行时自检与全部验收的基准。

## 5. 构建

```
node build.js
```

一条命令，六步，从你提供的原始素材重建全部生成物：

1. `world.execute (me) ;.mid` → `assets/onsets.js`（实测卡点表）
2. `Mili - world.execute (me) ;.mp3` → `assets/waveform.js`（实测时长 + 能量包络）
3. `world.execute(me)-timeline.lrc` → `assets/timeline.js`（cue 表 + scene id）
4. 由这些 cue 推导 → `src/01_world.js`（世界曲线）
5. 把歌词文本注入 `index.html`（第二份、逐字节的拷贝）
6. 交叉校验所有生成物

**第 6 步会拒绝构建。** 它检查内嵌歌词副本与 cue 表是否逐毫秒一致、cue 时间是否严格递增、
scene id 是否唯一、时长是否来自实测。

### 场景 id 表为什么要写三列

`_build/scenes.js` 每一行长这样：

```js
[71,  'lf.you1',  'you have left'],     // 序号, scene id, 必须出现在该句歌词里的一个词
```

一开始这张表只有 scene id，靠**位置**对齐。它在中段少了三条、又在结尾多了三条，
**总数是对的**，于是整幕处决戏会被静默映射到错误的歌词上。
只靠位置抓不到这种事；序号 + 一个来自那一句的词可以，而且它**让构建失败，而不是让首映失败**。

五套检查，全部通过（`--verbose` 看逐块数字）：

| 检查 | 覆盖 |

| `build.js` | 全部生成物可从原始素材重建，且互相一致 |

### 四条最关键的证明

**① 跳转安全，是可执行的断言而不是希望。**
无头画布会**记录每一次绘图调用**，把调用流哈希成帧指纹：

```
ok   the same t renders identically on a repeat pass  —  112 frames hashed and matched
ok   a shuffled seek reproduces every frame           —  112 frames visited out of order, all identical
ok   seeking end -> start -> end returns the same frame
```

**② 覆盖率验证的是"画出来了"，不是"注册了"。**
`check-plates.js` 数的是真实图元（`moveTo/lineTo/fillText/arc/…`）。
一个只验证"注册了"的覆盖率检查曾经在**每一块画板都在抛异常、什么都没画**的情况下报 100%。

**③ 全片没有静止的画面。**
`gap-check.js` 在 0.15 秒步长下走完 1413 个采样点：**0** 帧与上一帧相同，且每一帧都有内容。

**④ 标注层上的数字必须是真的。**
见第 3 节。曾经有四个寄存器在跳假时钟、两列无意义数字雨——现在每个值都能追溯到一个真实量。

### 看画面

```
node _tools/render-png.js 30 75 158        # 指定秒数导出 PNG
node _tools/contact-sheet.js 20 5          # 接触印相，一眼看到全片弧线
```

`_tools/render-png.js` 是一个小型软件光栅器：它驱动**真实的画板代码**，把调用画进像素缓冲。
它不假装是浏览器 —— 文字画成方块、不做抗锯齿、**不模拟泛光与合成器** —— 所以实际浏览器里会更亮。
但**几何是忠实的**：东西在哪、多大、谁盖住谁。那正是构图评审需要、而数值检查看不见的一类问题。

## 7. 工具链自己的三个 bug（这一节比作品更值得读）

这个项目反复印证同一件事：**当你用工具去判断作品对不对时，先确认工具是对的。**

**① 软件光栅器缺了 `strokeStyle` / `fillStyle`。**
`ctx.strokeStyle = 'rgba(...)'` 只是加了一个没人读的自有属性，于是每一次描边和填充都退回白色：
整片白底白字。看起来像作品坏了，实际是工具坏了。四行探针找出来的。

**② 同一个光栅器把渐变近似成色相均值。**
径向渐变于是变成一块死灰，画面上出现一道硬竖直缝。改成逐像素真实求值后才对。

**③ 修好之后它立刻抓到两个真 bug：**
- `bg()` 里底色填充的顺序错了——那层 alpha=0.05 的扫描栅格状态把整幅底色和后面所有几何涂成
  1/30 强度，画面几乎是空的。
- **`pal()` 被参数 `p` 遮蔽**（`pal is not a function`），第六幕 25 块画板全哑。
  用一次性脚本把七幕的 674 处 `pal()` 换成 `PAL()`，从根上消除这一类遮蔽。

**④ `verify.js` 里的静态检查也已经抓到两次真错误。**
`M.bracket(...)` 和 `M.dim(...)` —— 这两个辅助函数在 `D` 上，不在 `M` 上。
现在有一条 regex 扫描所有画板文件，确认每一个 `M.xxx()` 都在 `M` 的导出里。

**⑤ 最后还有一个我自己犯的：用 PowerShell 做批量文本替换。**
```
(Get-Content f -Raw) -replace 'A','B' | Set-Content f
```
在 Windows PowerShell 5.1 里这不是文本编辑，是**重新编码**：`Get-Content -Raw` 把 UTF-8 文件按
ANSI 代码页读入，`Set-Content` 再按同样方式写出，于是每个非 ASCII 字符被双重编码——
破折号变成了 `U+9225 U+003F`。
恢复脚本 `_build/repair-encoding.js` 因此存在，而它自己的前三个版本也各有各的错
（守卫把注释续行判成代码、把单行块注释判错、在自己的块注释里放了终止符）。
最后的版本改成**用结果校验**：先替换、再解析、解析通过才写入。

**⑥ 颜色解析器只认整数。**
`EM.mix` 返回的是**没取整的浮点数**，所以混合色到达光栅器时是
`rgba(186.4,242.35,231.55,0.55)`。解析器的正则只匹配整数，于是**每一个混合色都解析失败**，
回退成白色默认值——好几帧因此渲染成"黑底上一层淡淡的白雾"。
作品画的是细线，是工具把它涂成了白色。

**⑦ 文字在光栅器里一直是错的颜色。**
`fillText` 把颜色**拆成四个参数**传给了签名为 `(x, y, w, h, paint, alpha)` 的 `rect`，
于是 `paint` 拿到了红通道、`alpha` 拿到了绿通道。**所有文字在预览里都是深色或白色方块。**
这个调用从渐变重构改了 `rect` 签名起就错了，一直没人发现——因为**文字方块出现的位置是对的**，
只有颜色是胡说。它让我一度以为结尾那个居中的 EXECUTION 没画出来。

**这一节里每一个 bug 都有同一个形状：症状看起来像作品的问题，其实是工具的问题。**

## 8. 一条关于"加料"的教训

修"空帧"的第一反应是**加东西**：一层常驻标注、更密的底板、更多读数。
结果是"中间没有一点空隙，越看越窒息"——**密度没有喘息就是疲劳，而疲劳不是强度。**

所以现在有一条 `breath(t)` 包络：全片以约 15 秒的周期呼吸，标注层与世界层一起降到约 46%，
再张开；在处决风暴那段降到最低。它永不关闭（画面仍不能空），而且它是 `t` 的纯函数。

配套的是 `near()` 与 `faint()` 的区分：`faint` 按 `GAIN` 压暗**背景**，
`near` 只按呼吸包络调制**主体**（拓扑形状——格子、波、乱麻、开环曲线）。
把主体也一起压暗是**过度的主次处理**：把背景推远的目的是让主体被看见，不是让主体消失。

## 8. 想用你自己的 AI 再做一遍

这个仓库是一个完整的"输入 → 输出"样本，可以整套换掉。

**三个输入文件**：音频（时间的唯一真相）、MIDI（真实演奏的卡点来源）、LRC（歌词落点）。

**可以拿去用的一段话：**

> 请使用我提供的《world.execute(me);》音频、MIDI 与 LRC 文件创作一部完整的网页动画。
>
> 先解析 MIDI，把每个音符的起始时刻、音高、力度提取成数据嵌进代码，用于所有卡点；
> 歌词时间轴以 LRC 实测时间为准，不要用固定 BPM 网格去套。这两件事分工不要混。
>
> 逐句理解歌词的情绪，为每一句设计独立的视觉表达；重复出现的歌词必须根据上下文变化
> ——如果 `EXECUTION` 出现 18 次，就要有 18 种不同的处理，而且最好用**一个参数化工厂**
> 生成，让它读起来是一个实体在变化，而不是 18 张无关的幻灯片。
>
> 以 `audio.currentTime` 作为唯一时间基准，用 `requestAnimationFrame` 驱动。
> **区间内的渲染必须是时间的纯函数**：不要有任何跨帧可变状态，不要用 `Math.random()`，
> 所有随机取自 `(序号, t)` 的哈希。这样往回拖进度条才不会花屏，跳转后才能精确复原。
>
> 最终必须能直接双击 index.html 运行，不装依赖、不构建、不起服务器、不联网；
> 歌词与时间轴保存在本地代码中。
>
> 完成后请自己写脚本验证，并且注意：**覆盖率要验证"画出来了"，不能只验证"注册了"**。
> 至少还要验证：动画终点与实测音频时长一致、任意乱序跳转后逐帧复原、无资源缺失、
> 音频缺失时能降级而不是黑屏、单块画板抛异常不会毒死整个渲染循环。
